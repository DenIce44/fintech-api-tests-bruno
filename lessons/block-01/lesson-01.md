# Блок 1. Занятие 1 — первый API-запрос и первые проверки в Bruno

**Продолжительность:** 90 минут  
**Формат:** 20% объяснение, 80% практика  
**Результат занятия:** локальный Git-репозиторий с Bruno-коллекцией, одним проверенным `GET`-запросом и успешным запуском из Bruno Desktop и Bruno CLI.

## Что вы научитесь делать

К концу занятия вы сможете:

- объяснить, из чего состоят HTTP-запрос и HTTP-ответ;
- отправить `GET`-запрос в Bruno;
- вынести адрес API в environment-переменную;
- проверить статус, заголовок и JSON-тело ответа;
- понять причину падения простой проверки;
- запустить Bruno-коллекцию из терминала;
- сохранить результат работы первым осмысленным Git-коммитом.

## Что понадобится

- компьютер с доступом в интернет;
- [Bruno Desktop](https://docs.usebruno.com/get-started/bruno-basics/download);
- [актуальная LTS-версия Node.js](https://nodejs.org/en/download) вместе с npm;
- [Git](https://git-scm.com/downloads);
- любой редактор кода;
- терминал.

> Для этого занятия не нужны аккаунт, токен, банковские данные или другие секреты. Используется публичный учебный Postman Echo API.

## 1. Разберите один HTTP-запрос — 10 минут

Сегодня будет отправлен запрос:

```http
GET https://postman-echo.com/get?lesson=1
```

Запомните четыре части:

1. `GET` — HTTP-метод. Он запрашивает данные и не должен изменять их на сервере.
2. `https://postman-echo.com/get?lesson=1` — URL ресурса. Параметр `lesson` передаётся серверу в query string.
3. Заголовки ответа описывают ответ. Например, `Content-Type` сообщает формат тела.
4. Тело ответа содержит данные. В этом занятии ожидается JSON с объектом `args` и полем `args.lesson`.

Смысл первой проверки можно записать по схеме Arrange–Act–Assert:

- **Arrange:** выбран environment `local`, в нём задан `baseUrl`;
- **Act:** отправлен `GET {{baseUrl}}`;
- **Assert:** статус равен `200`, ответ имеет формат JSON, поле `args.lesson` существует и является строкой.

## 2. Проверьте инструменты — 15 минут

Откройте терминал и выполните команды по одной:

```bash
git --version
node --version
npm --version
```

Ожидаемый результат: каждая команда выводит номер версии без ошибки.

Если команда не найдена:

- установите соответствующий инструмент по ссылкам из раздела «Что понадобится»;
- полностью закройте и снова откройте терминал;
- повторите проверку версии.

Используйте актуальную LTS-версию Node.js. Документация Bruno допускает Node.js 18 и новее, но устаревшую ветку специально устанавливать не нужно.

## 3. Создайте проект и установите Bruno CLI — 10 минут

В терминале перейдите в папку, где будут храниться учебные проекты, затем выполните:

```bash
mkdir fintech-api-tests-bruno
cd fintech-api-tests-bruno
git init
npm init -y
npm install --save-dev @usebruno/cli
npx bru --version
```

Почему CLI устанавливается локально через `--save-dev`:

- версия сохраняется в `package.json` и `package-lock.json`;
- другой человек сможет установить ту же зависимость командой `npm ci`;
- для запуска не требуется глобальная установка Bruno CLI.

Создайте в корне проекта файл `.gitignore`:

```gitignore
node_modules/
reports/
.env
.env.*
!.env.example
*.secret.bru
.DS_Store
```

Создайте рядом файл `AGENTS.md`, чтобы Codex соблюдал правила учебного проекта:

```markdown
# Правила проекта

- Не добавляй секреты, реальные персональные данные и платёжные реквизиты.
- Храни Bruno-запросы и тесты в `.bru`-файлах.
- Используй Safe Mode, если нет обоснованной необходимости в Developer Mode.
- После изменения запускай затронутые тесты.
- Для каждой проверки объясняй, какое требование она покрывает.
```

Проверьте себя:

- в папке есть `package.json` и `package-lock.json`;
- `npx bru --version` выводит версию;
- папка `node_modules` не отображается среди будущих файлов Git.
- правила безопасной работы с ИИ записаны в `AGENTS.md`.

## 4. Создайте коллекцию, environment и запрос — 15 минут

### 4.1. Коллекция

1. Откройте Bruno Desktop.
2. На домашнем экране нажмите `+` → **Create Collection**.
3. Укажите имя `fintech-api`.
4. Откройте дополнительные настройки расположения.
5. В качестве расположения выберите родительскую папку `<папка проекта>/bruno`. Не добавляйте `fintech-api` к пути вручную: Bruno сам создаст папку с именем коллекции.
6. Выберите формат **BRU** и нажмите **Create**.
7. В настройках коллекции оставьте JavaScript sandbox в **Safe Mode**.

После этого файл конфигурации должен находиться точно по пути `bruno/fintech-api/bruno.json`. Путь `bruno/fintech-api/fintech-api/bruno.json` означает, что имя коллекции было продублировано в выбранном расположении.

### 4.2. Environment

1. В правом верхнем углу нажмите **No environment**.
2. В секции коллекции нажмите **Create**.
3. Назовите environment `local`.
4. Добавьте переменную:

   | Name | Value |
   |---|---|
   | `baseUrl` | `https://postman-echo.com` |

5. Сохраните environment и выберите `local` в выпадающем списке.

Регистр важен: в инструкции везде используется одно имя — `baseUrl`.

### 4.3. Запрос

1. В коллекции создайте папку `00-learning-basics`.
2. Внутри папки создайте новый HTTP-запрос.
3. Укажите имя `01-echo-get`.
4. Выберите метод `GET`.
5. В поле URL введите `{{baseUrl}}/get?lesson=1`.
6. Сохраните запрос.
7. Нажмите **Send** или `Cmd/Ctrl + Enter`.

Ожидаемый результат:

- статус ответа — `200 OK`;
- тело ответа отображается как JSON;
- в теле есть объект `args` и поле `args.lesson` со строковым значением `"1"`.

> Если при запросе `GET https://echo.usebruno.com` вы получили `404 Not Found`, Bruno настроен правильно: этот сервер принимает echo-данные через `POST`, но не обслуживает `GET /`. Используйте GET-маршрут из этой инструкции.

## 5. Добавьте четыре декларативные проверки — 15 минут

Откройте вкладку **Assert** в запросе и добавьте строки:

| Expression | Operator | Value | Что проверяет |
|---|---|---|---|
| `res.status` | `equals` | `200` | запрос завершился успешно |
| `res.headers['content-type']` | `contains` | `application/json` | сервер вернул JSON |
| `res.body.args.lesson` | `isDefined` | оставить пустым | обязательное поле существует |
| `res.body.args.lesson` | `isString` | оставить пустым | поле имеет ожидаемый тип |

Повторно отправьте запрос и откройте результаты тестов. Все четыре проверки должны быть зелёными.

Дополнительно откройте вкладку **Tests** запроса и повторите те же идеи на JavaScript с Chai:

```javascript
test("status is 200", function () {
  expect(res.getStatus()).to.eql(200);
});

test("content type is JSON", function () {
  expect(res.getHeader("content-type")).to.include("application/json");
});

test("body contains a string lesson argument", function () {
  const body = res.getBody();

  expect(body).to.have.property("args");
  expect(body.args).to.have.property("lesson");
  expect(body.args.lesson).to.be.a("string");
});
```

Снова отправьте запрос. Декларативные assertions и JavaScript-тесты должны пройти.

## 6. Создайте, прочитайте и исправьте падение — 7 минут

1. В первой декларативной проверке временно замените ожидаемый статус `200` на `201`.
2. Отправьте запрос.
3. Найдите красную проверку и проговорите вслух:

   - что ожидал тест;
   - что фактически вернул сервер;
   - является ли проблемой API или неверное ожидание теста.

4. Верните ожидаемый статус `200`.
5. Запустите запрос ещё раз и убедитесь, что все проверки снова зелёные.

Главный навык на этом шаге — не просто увидеть красный тест, а сравнить **expected** и **actual**.

## 7. Запустите коллекцию через Bruno CLI — 10 минут

Сохраните все изменения в Bruno. Из корня проекта `fintech-api-tests-bruno` сначала перейдите в папку, где непосредственно лежит `bruno.json`, а затем запустите CLI:

```bash
cd bruno/fintech-api
npx bru run -r --env local
cd ../..
```

Bruno CLI нужно запускать из корня коллекции — папки с `bruno.json`. Флаг `-r` нужен, потому что запрос находится во вложенной папке `00-learning-basics`. Bruno CLI версии 3 запускает JavaScript в Safe Mode по умолчанию, поэтому для этого занятия не нужен `--sandbox=developer`.

Если у вас уже получилась двойная папка `bruno/fintech-api/fintech-api`, для текущей структуры используйте:

```bash
cd bruno/fintech-api/fintech-api
npx bru run -r --env local
cd ../../..
```

Успешный результат:

- CLI нашёл и выполнил `01-echo-get`;
- запрос завершился статусом `200`;
- все assertions и тесты прошли;
- команда завершилась без ошибки.

Если CLI сообщает, что environment не найден, проверьте:

- сохранён ли environment внутри коллекции;
- действительно ли он называется `local`;
- появился ли файл environment в `bruno/fintech-api/environments`.

Если CLI не нашёл ни одного запроса, проверьте наличие флага `-r` и сохраните запрос в Bruno.

Если CLI выводит `You can run only at the root of a collection`, выполните `pwd` и `ls`: в текущей папке должен непосредственно находиться `bruno.json`.
